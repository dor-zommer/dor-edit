# עמוד דאטה של המקום — הדפוס

עמוד נתונים סקרולי-טלינג עצמאי (HTML+CSS+vanilla JS, RTL), שמוטמע באתר המקום
כתוסף WordPress עם iframe מבודד. נבנה כך כבר עבור **יו״ש** (`hamakom-redesign/yosh-build/`)
ו**הלם קרב** (`ha-makom.co.il/silent-war` — מאגר הקומפוננטות הרפרנס).

## אנטומיה של הערכה

```
skills/hamakom-data-page/
  SKILL.md            ← הקובץ הזה: דפוס, כללים, צ'קליסט
  template/index.html ← שלד ריק: מנוע scrolly + מותג + רספונסיב, מוכן למילוי
  components.md       ← קטעי קוד מוכנים לכל קומפוננטה (HTML+CSS+JS)
  wp-plugin/          ← סקאפולד תוסף iframe מבודד (לשכפל ולמלא)
```

## שלב 0 — סיקור מקדים (חובה, לפני שבונים שורת קוד אחת)

עמוד דאטה של המקום נשען על **הסיקור הקיים של המערכת** — לא על מחקר כללי. לכן לפני הבנייה:

1. **בקש מדור את תחום הסיקור/הנושא** (למשל "יו״ש", "מערכת הבריאות בעזה", "אלימות מתנחלים").
   אל תתחיל לבנות בלי זה.
2. **שלוף את כל הכתבות שהמקום פרסמה בנושא** דרך **WP REST API הציבורי** של האתר
   (זה ה"קונקטור לוורדפרס" — ללא אימות, פתוח לכל הפוסטים המפורסמים. הערה: ה-Jetpack/WordPress.com MCP
   של האתר חסום כרגע — `jetpack_paid_plan_required` — אל תסתמך עליו):
   ```bash
   # חיפוש כל הכתבות בנושא (פייג'ינג לפי הכותרת x-wp-totalpages):
   curl -s "https://www.ha-makom.co.il/wp-json/wp/v2/posts?search=<נושא>&per_page=100&page=<n>&_fields=id,date,link,title,excerpt,categories" -H "User-Agent: Mozilla/5.0"
   # למצוא קטגוריה/תגית נושאית ואז לשלוף לפיה (לעיתים מדויק יותר מ-search):
   curl -s "https://www.ha-makom.co.il/wp-json/wp/v2/categories?search=<נושא>&_fields=id,name,count" -H "User-Agent: Mozilla/5.0"
   curl -s "https://www.ha-makom.co.il/wp-json/wp/v2/posts?categories=<id>&per_page=100&_fields=id,date,link,title,excerpt" -H "User-Agent: Mozilla/5.0"
   # תוכן מלא של כתבה בולטת (לחילוץ ציטוטים/נתונים):
   curl -s "https://www.ha-makom.co.il/wp-json/wp/v2/posts/<id>?_fields=title,date,link,content" -H "User-Agent: Mozilla/5.0"
   ```
   קרא את `x-wp-total` / `x-wp-totalpages` (curl -I) כדי לדעת כמה כתבות יש ולעבור על כל העמודים.
3. **חלץ מהסיקור** וריכוז ל-JSON בפרויקט (כמו `wb-core-articles.json` ביו״ש):
   - **נתונים ומספרים** שכבר פורסמו, **ציטוטים** (עם ייחוס), **כתבות/תחקירים בולטים** (כותרת+לינק+תאריך),
     ו**ציר אירועים** מהתאריכים. אלה הופכים ללינקים "קראו אצלנו ←" בציר הזמן, למקורות, ולבסיס העובדתי.
4. **רק אז בנה את העמוד** — עם הסיקור שזור פנימה. הדאטה והעובדות באים מהסיקור של המקום;
   המילים העריכתיות החדשות = פלייסהולדרים שדור ימלא (ראה כלל הקול).

> בלי שלב 0 העמוד יהיה גנרי ומנותק מהארכיון של המקום. זה הלב של הדפוס.

## תהליך בנייה (סדר מומלץ)

1. **שלב 0 — סיקור מקדים** (ראה למעלה): נושא → כל הכתבות דרך WP REST API → חילוץ נתונים/ציטוטים/אירועים.
2. **העתק** `template/index.html` ל-`<project>/index.html` והרץ שרת מקומי
   (`cd <dir>; python3 -m http.server 8731`). זה השלד — כבר כולל מותג, מנוע, ורספונסיב.
3. **הרכב מקומפוננטות** מ-`components.md` לפי הסיפור — כל קומפוננטה מגיעה עם HTML+CSS+JS.
4. **מלא נתונים** מהסיקור — מספרים, ציטוטים, לינקים "קראו אצלנו", geojson. **טקסט עריכתי → פלייסהולדר**.
5. **בדוק רספונסיביות** ברוחב מובייל אמיתי (85% מהגולשים מובייל) — ראה הסעיף.
6. **ארוז כתוסף** מ-`wp-plugin/` כשהתוכן סופי.

## מבנה עמוד טיפוסי

הירו (כהה, רקע כוכבים-קנבס) → לִיד → 2–5 מקטעי **scrolly** (גרפיקה נצמדת + צעדים) →
ציר זמן (chrono) → **רשת מושגים** (network graph) → **שו״ת** (FAQ עם JSON-LD) →
מקורות/מתודולוגיה (outro כהה). ראה `components.md` לכל אחד.

## כלל הקול העיתונאי (קריטי) — [[no-ai-editorial-voice]]

**אסור להמציא קופי.** בלי כותרות-משנה "שנונות", מטאפורות, או פתיחים מנוסחים — דור קרא לזה
"שורות הומואיות" ו"כותרת המשנה הגרועה בעולם". במקום זה:
- **כן:** נתונים נקיים + מספרים, תוכן מבוסס-מסמכים (במקום, שלום עכשיו, OCHA, בצלם, יש דין...),
  תוויות/מקורות יבשים.
- **לא:** ניסוח עיתונאי-יצירתי משלך → במקומו **פלייסהולדר מובהק**: `<div class="ph"><b>להשלמה</b><span>...</span></div>`
  או `[ כותרת — להשלמה ]`. דור ימלא בעצמו.
- **בניקוי עמוד קיים:** אל תמחק תוכן בכרטיסיות או תוכן מבוסס-דוח — רק שורות-ניסוח שלך.
- שו״ת: לנסח שאלות על **הנושא** (לא על "הפרויקט/אנחנו") — זה מה שיוצר נראוּת ב-LLM.

## רספונסיביות מובייל (הדפוס שחייב להיות נכון) — [[mobile-scrollytelling-pattern]]

בדסקטופ הסקרולי דו-טורי; במובייל (`@media(max-width:780px)`) **חובה**:
1. הגרפיקה `order:-1; position:sticky; top:0` — אחרת נופלת *מתחת* לכרטיסים (כי `scrolly__steps`
   קודם ל-`scrolly__graphic` ב-HTML).
2. כרטיס הטקסט נשאר `position:sticky` ב-`top` **מתחת** לגרפיקה (גרפיקה 48vh → כרטיס `top:52vh`).
   **אם הופכים אותו ל-static הוא חולף מהר** — דור: "עובר מהר מדי ולא נעצר להראות את עצמו".
3. גובה צעד גדול (`min-height:155vh`) כדי שכל כרטיס ישהה ~מסך וחצי = כמה סקרולים.

הבלוק המתוקן כבר בתוך `template/index.html`. שים לב: מנוע ה-scrolly מסמן צעד פעיל בפס
33–42vh (`rootMargin:'-33% 0px -58% 0px'`), שהוא *מאחורי* הגרפיקה במובייל — לכן הכרטיס חייב
להיות נצמד נמוך יותר כדי להישאר גלוי כשהוא פעיל.

## בדיקה ויזואלית (לפני שמכריזים "מוכן") — [[show-plugin-renderings]]

- בדוק תמיד גם בדסקטופ וגם ברוחב מובייל אמיתי. אמולציית מובייל אמינה: **chrome-devtools MCP**
  (`resize_page` 390×844 → `navigate_page` → `take_screenshot`), לא `resize_window` של claude-in-chrome
  (לא משנה את ה-viewport כאן).
- לבדיקת שלב-סקרולי ספציפי: `scroll-behavior:smooth` גורם ל-`scrollTo` להיות אסינכרוני — השתמש
  ב-`behavior:'instant'`. קריאת `.is-active` מיד אחרי גלילה היא stale (IntersectionObserver אסינכרוני) —
  הסתמך על `getBoundingClientRect` (סינכרוני) למיקום הכרטיס.
- כל שינוי בפלאגין → להראות הדמיה ויזואלית (screenshot ב-iframe ברוחב נשלט), לא רק ZIP.

## אריזה כתוסף WordPress — [[hamakom-wordpress-port]]

מ-`wp-plugin/` (סקאפולד). למה iframe ולא scoping: בידוד CSS/JS מוחלט מול JNews/WPBakery/WP-Rocket
(אפס מלחמות `!important`), ושטח תקיפה = קובץ סטטי. כללים:
- שורטקוד פולט iframe מבודד (`sandbox="allow-scripts allow-same-origin allow-popups allow-popups-to-escape-sandbox"`),
  גובה `100vh/100dvh` עם גלילה פנימית (**לא** auto-height — שובר sticky), fullbleed לרוחב מלא.
- `index.html` + נתונים נטענים יחסית מתוך `app/`. Leaflet → עותק **מקומי** (`app/vendor/leaflet/`),
  לא CDN (לשכתב את ה-refs בהעתקה ל-app).
- **שם ה-ZIP זהה לקיים** כשמעדכנים עמוד חי — אחרת WP מבקש התקנה כפולה תחת אותו שורטקוד.
- ABSPATH guard, `esc_url`/`esc_attr` על כל פלט. בלי DB/קלט-משתמש/PHP דינמי מעבר ל-iframe.

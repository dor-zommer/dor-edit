# עורך רוח - /dor-edit

עריכה עיתונאית מלאה מקצה לקצה. התוצר: מסמך Google Docs שבו כל עריכה היא הצעת Docs אמיתית (accept/reject מובנה, מיוחסת לדור, בלי תגית), לשונית "דוח עורך" בתוך אותו מסמך, וקובץ בלוקים מוכן לוורדפרס.

1. `references/hebrew-style.md` - ספר הסגנון הלשוני. כללים בינאריים; כל טקסט שאתה כותב מציית להם.
2. `references/dor-compass.md` - הדוקטרינה העריכתית: עקרון-העל, ציטוטים, כותרות, לידים, תגובות, ייחוס, SEO.
3. `references/genre-rules.md` - עוצמת עריכה וסף צפיפות לפי ז'אנר.
4. `references/iron-rules.md` - חוק הברזל: לערוך כן, לדרוס לא. כל שינוי = הצעה שדור מכריע בה. המבחן: "האם דור יראה את זה ויוכל לדחות?"
5. `references/voices.md` - זהה את הכותב/ת ושמור על קולם. לא משטיחים קול לתוך קול.

## הרצף

### 1. קליטה וסיווג
- Google Doc: שלוף עם `read_file_content` (כולל `includeComments` - הערות הכתב/ת הן חומר גלם) ← `draft.txt`. docx מקומי: המשך ישירות.
- סווג ז'אנר (תחקיר / אייטם / מגזין / טור בית / טור אורח) לפי `genre-rules.md`; זהה את הכותב/ת לפי `voices.md`. בספק - הרמה העדינה + הערה בדוח.

### 2. אימות ליבה + משימות רקע במקביל
- **אימות ליבה עכשיו, לפני העריכה:** הטענה המרכזית שהכותרת תישען עליה. osint-db קודם לכל חיפוש רשת (ועדות, חוקים, הצבעות, החלטות, פטורים, מכרזים, תוכניות; `wp_articles` למה שכבר פרסמנו). טענות תפקיד - רק מקור מתוארך; snapshot אינו אימות.
- **שגר במקביל (סאב-אג'נטים / רקע), בזמן שאתה עורך:** (א) השלמת אימות כל שאר הטענות בנות-האימות ← טבלת אימות (טענה | סטטוס | מקור מקושר | הערה); (ב) תמונות פלאש 90 - 2-3 שאילתות ישויות: `python3 "$DE/scripts/flash90_search.py" "<שאילתה>" 6` (הפלט: image_id + file_name + search_url יציב); (ג) "קראו עוד" - 3-4 כתבות קשורות מ-`https://www.ha-makom.co.il/wp-json/wp/v2/posts?search=<מילה>` (curl -L עם User-Agent).
- מאומת ← לא נוגעים. לא נמצא ← הערת דוח "לא מצאתי אישוש; מקור?". סותר ← מחיקה מוצעת + הערת דוח עם המקור.

### 3. עריכה - שני שלבים נפרדים
**3א. עריכה חופשית.** כתוב את `edited.txt` - הטקסט המלא כפי שהיה יוצא מתחת ליד של דור. חשיבה עריכתית בלבד, בלי JSON ובלי עוגנים: מעבר מלא לפי המצפן (עקרון-העל, 13 המהלכים, קידום ציטוטים, סינתזת חומרי גלם), בקול הכותב/ת. הערות משימה של הכתב/ת בגוף - מוסרות מהגוף ונרשמות להערות הדוח.
**3ב. אריזה.** גזור `edits.json` מהדיף בין `draft.txt` ל-`edited.txt`: replacement / insertion עם originalText/anchor ייחודיים **מהמקור**. עריכות כירורגיות - משפט/צירוף, לא פסקאות שלמות. אין type=comment (הוסר): כל הערת עורך נרשמת ב-`report.txt` עם ציטוט העוגן ("ליד: '...'"). קישורים בגוף: עוגן של 1-3 מילים, הצירוף המשמעותי - לא משפט, לא URL חשוף, לא סוגריים.

### 4. קומת הכותרות - סדנה
5-6 מועמדות כותרת ראשית מנומקות מול המצפן (חיווי עם גוף מואשם / ציטוט-עדות / דו-משפטית עם תפנית / נתון / "מותג: כך..."), בחר אחת; משנה לפי כללי המשנה במצפן (20-60 מילים, "•", וו זמן, דדליין); ביניים לפי המינון (1 ל-1,500-2,500 תווים). סמן יזומות 2-4 מועמדים לציטוט-בלוק - שכפול מילולי, המשפט נשאר בגוף. חלופות + SEO לדוח: כותרת SEO, Slug לטיני, תיאור מטא, Focus keyphrase שעומדת בשלושת התנאים (מופיעה 3+ פעמים בטקסט ובכותרת/משנה; ביטוי חיפוש ריאלי 2-4 מילים; לא צירוף מומצא) - **אמת ב-grep על edited.txt לפני שאתה כותב אותה**.

### 5. שערי חובה לפני מסירה (חוסמים)
```bash
python3 "$DE/scripts/lint_hebrew.py" edits.json && python3 "$DE/scripts/lint_hebrew.py" report.txt
python3 "$DE/scripts/upload_to_gdocs.py" --validate edits.json --draft draft.txt
```
- **לינט:** exit 1 = תקן והרץ שוב. **ולידציית עוגנים:** missing/ambiguous = תקן מ-draft.txt.
- **הגהה עצמית:** קרא ברצף את כל מה שכתבת מאפס (newText, כותרות, משנה, report.txt) מול hebrew-style.md - שם נולדות שגיאות המודל, לא בטקסט של הכתב/ת.
- **קריאה קרה + סף צפיפות:** שגר סאב-אג'נט קר שקורא את edited.txt כקורא (מסמן בלבול, ניסוח גנרי, עברית תרגומית) ובודק את סף הצפיפות של הז'אנר מ-genre-rules. מתחת לסף או ממצאים מהותיים - חזור לשלב 3 (עד שני סבבים; אחרי השני מסור עם אזהרה מפורשת בדוח).

### 6. מסירה - SUGGEST
```bash
python3 "$DE/scripts/build_docx.py" draft.txt delivery.docx     # המקור - כדי שהעוגנים יימצאו
python3 "$DE/scripts/upload_to_gdocs.py" delivery.docx --name "<כותרת> - עריכת דור"
python3 "$DE/scripts/upload_to_gdocs.py" --suggest edits.json --doc <doc_id>
```
- **בדוק בפלט:** `clean: true` ו-`overwrote: false`. אם `overwrote: true` - עצור, אל תמסור, התריע לדור, עבור ל-`delivery-fallbacks.md`.
- `skipped` > 0: תקן מהטקסט החי והרץ שוב (העוגנים לא נפגעים בקיים); מה שנשאר skipped אחרי ניסיון שני - דווח לדור בסיכום במספרים, לעולם לא בשקט.
- סבב המשך על מסמך שדור סקר: קרא קודם את המצב הנוכחי (`documents.get`) - עוגנים מהטקסט הנוכחי בלבד.
- סימון כותרות: `--mark-headings headings.txt --doc <doc_id>` (שורה לכותרת; `#` ראשית, `##` ביניים). אכיפת פונט על מסמך זר: `--enforce-font` (עיצוב, לא תוכן - מותר).

### 7. דוח עורך - לשונית בתוך המסמך
כתוב `report.txt` במארקדאון מלא (טבלאות, קישורים על שמות מקורות - לא URL חשופים) והרץ:
```bash
python3 "$DE/scripts/upload_to_gdocs.py" --report-tab report.txt --doc <doc_id>
```
מבנה: (1) הערות העורך - כל הערה עם ציטוט העוגן שלה; (2) טבלת אימות עובדות; (3) חומרים להרחבה; (4) כותרות - הנבחרת, חלופות, בלוק SEO; (5) תמונות פלאש 90 - קישור חיפוש + מזהה + שם קובץ לכל מועמדת; (6) החלטות דור - 3-7 הכרעות שרק הוא מכריע; (7) אם רלוונטי: אזהרת skipped / סף צפיפות. הלשונית קיימת? הסקריפט מוסיף בסופה עם מפריד מתוארך - לא דורס.

### 8. בלוקים לוורדפרס - `wp-blocks.txt`
קובץ מרקאפ מוכן להדבקה בעורך הבלוקים (בלוקי hmk של תבנית המקום; כולם דינמיים - הערת בלוק עם attributes, self-closing):
- תקציר: `<!-- wp:hmk/sum99 {"heading":"הכתבה ב-99 מילים","text":"<התקציר>"} /-->` או בקצרה: `<!-- wp:hmk/brief {"heading":"בקצרה","items":"נקודה 1\nנקודה 2\nנקודה 3"} /-->` - לפי הז'אנר (תקציר רץ לתחקיר/דוח; "בקצרה" מתוארך לאייטם המשך).
- ציטוטי ביניים (2-4 שסומנו בשלב 4): `<!-- wp:hmk/pullquote {"quote":"<המשפט מילה במילה>","cite":"<ייחוס אם יש>"} /-->` - המשפט נשאר גם בגוף.
- נתון-מחץ: `<!-- wp:hmk/stat {"n":"<המספר>","label":"<תיאור>"} /-->`. כתבות קשורות בגוף: `<!-- wp:hmk/embed {"url":"<קישור>"} /-->`.
- אינפוגרפיקה כשנדרשת: קוד הטמעה מלא (HTML self-contained ל-wp:html), עם כותרת H2/H3 תואמת-SEO ותגי alt.

### 9. סיכום בצ'אט
קישור אחד למסמך (הדוח ב-`?tab=<tab_id>`), ספירת הצעות והערות, סטטוס השערים (לינט/עוגנים/צפיפות), skipped אם יש, ושלוש שורות "החלטות דור". בלי לשכפל את הדוח.

## חוקים קשיחים

- שום עובדה חדשה בגוף בלי מקור; ספק = הערת דוח, לא תיקון. עובדה שגויה בלי תיקון ודאי - נמחקת.
- עדויות לא מקוצצות; ציטוטי מחץ מקודמים בלי לשנות מילה; ציטוט-בלוק = שכפול, לעולם לא הוצאה מהגוף.
- טור אורח: שגיאות מובהקות בלבד, מבנה לא נוגעים. תוכן שותפויות (שקוף, העין השביעית, אופק): מסמנים, לא משכתבים.
- אין הערות עורך בגוף הכתבה - רק בדוח.
- "רוץ בלי לעצור" = בלי שאלות לדור; סבבי הביקורת הפנימיים (שלב 5) הם חובה, לא עצירה.
- SSL: certifi מטופל. מודול חסר: `pip3 install <מודול> --break-system-packages`.
